# Native-Speaker Review Pack (docs/21 workstream 4)

**Who this is for:** a native reviewer of Iraqi Arabic (`ar`), Kurdish Sorani (`ckb`), and Kurdish
Badini/Kurmanji (`kmr`). One person per language is fine; the same sheet works for all three.

**Why:** all ar/ckb/kmr text in `data/seed/` was machine-drafted by an LLM. It embeds and retrieves,
but nobody has verified it reads like something Asiacell would actually send a customer. Per docs/21
and docs/20, no entity moves to `status: "verified"` until its languages pass native review.

## How to run the review (one sitting, ~30–60 min at current size)

1. Work through the checklist below, string by string. For each string ask:
   - **Correct?** Same meaning as the English reference — no facts added, none dropped (docs/21 §3).
   - **Dialect?** Arabic must be **Iraqi colloquial**, not MSA ("شلون" not "كيف"). Sorani and
     Badini must not blur into each other.
   - **Natural?** Would a customer-care agent actually phrase it this way? Watch for known LLM
     typos (e.g. `بُكْمَة` instead of `باقة` — a failure mode already seen from the local model).
   - **Numbers/codes intact?** Prices, GB/MB, day counts, and USSD/shortcodes must match the
     English reference exactly. (Note: many codes are themselves PLACEHOLDERS — flag dialect/grammar
     anyway; the codes get replaced via the seed-20 worksheet.)
2. Tick the box if the string is fine as-is. If not, **write the correction inline** right under the
   string (or in a copy of this file / a spreadsheet — whatever is easiest to hand back).
3. Bonus, high value: for each entity, jot down **how customers colloquially say its name**
   (including romanized spellings like "combo", "kombo") — these become `aliases` and directly
   improve retrieval.

## Handing results back

Return the annotated file. Corrections get applied to the JSON in `data/seed/`, then:
`npm run ingest` → `npm run eval` (the regression gate, docs/09 §6).
